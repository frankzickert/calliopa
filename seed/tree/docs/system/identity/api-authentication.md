# API Authentication

## API Authentication

- This topic is a link since `BO_0207_016`. What it described — the shell's own client records, credential lifecycle and caller resolution at its external API — retired with the shell's stores; how a caller proves who it is is the core's now.
- Identity is the core's: a principal authenticates to CCGW and the kernel as `BO_0206` fixes, an identity class decides whether a caller writes truth or may only propose (`ccgw.md`), and the shell's server side reaches both under the kernel-held principal without holding a credential (`ui-kernel.md`, `BO_0207_001`).
- The shell keeps no database, no bucket key and no gateway of its own (`ui-shell.md`, `BO_0207`); the history of the retired implementation stays in this topic's earlier revisions.
- Since `BO_0206` (2026-09-07, authentication epoch at dataRevision 81) the core authenticates every mutation: CCGW resolves a core-issued `cck_` credential to exactly one principal or refuses, `context.principal` is an assertion checked against it, and the resolved name is the `createdBy` stamp. The shell holds no credential: its writes go through the kernel bridge, which presents the owner's. This line was staged from the CLI under the `claude` agent account as the change's own loop check.
- Since `BO_0209` (2026-09-08) a person is who the kernel's session says: the shell's server forwards the browser's `calliopa_session` cookie on every call it makes to the kernel — the bridge, the state record, the secret store, the agent surface and the account routes — so a served page reads and writes as the person whose browser asked for it, and the header's person menu names that person and offers sign-out ([Layout](../workspace/layout.md)). In prod the kernel's public port admits no anonymous browser past its own sign-in page (`ui-kernel.md`, `BO_0214_009`); the shell carries no sign-in screen and holds no credential or session secret. The people who hold authority are the settings extension's People section (`src/extensions/settings/docs/system/settings-surface.md`).
