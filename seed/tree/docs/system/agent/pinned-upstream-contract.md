# Pinned Upstream Contract

## The Pinned Upstream Contract

Hermes is an external Python distribution. Every item below was verified against the installed release and none of it is inferable from the upstream documentation alone.

* The pin is `hermes-agent==0.19.0` on Python 3.13. It is a pin, not `latest`.
* Two dependencies the base install misses and the image must add:
  * `aiohttp` — without it the API server silently reports "no adapter available".
  * `mcp>=1.24,<2` — the 2.0 SDK drops the legacy symbol the release's HTTP-transport gate probes for, disabling HTTP MCP entirely.

- A build-time patch extends Hermes's MCP-elicitation acceptance to the Calliopa tool server. In codex app-server mode the release auto-accepts elicitations only for its own injected `hermes-tools` server and declines every other one, including the toolset the stack explicitly configured. The patch carries an assertion that fails the build loudly if a pin bump moves the code, so the patch is re-evaluated at every bump rather than silently becoming a no-op.
- Node comes from the official `node:22` image rather than from Debian, whose `nodejs` is 20 on this base while both delegated CLIs declare `node >=22`. Installing them on 20 succeeds with an `EBADENGINE` warning and leaves an unsupported runtime to be found at the first real delegation, so the image asserts its Node major at build time. The tag matches the Python base's Debian release, so there is one libc in the image.
- `HERMES_HOME` relocates the config, the `.env`, and the SessionDB onto the named volume.
- The API server is enabled with `API_SERVER_ENABLED=true` behind `API_SERVER_KEY` on port 8642 inside the container. Hermes refuses a key shorter than 16 characters, and refuses the API server alone rather than the process: the gateway keeps running with no API server, so a healthcheck reading `/health` is what catches a short key rather than a container that exited.
- `/health` is the upstream half of the service healthcheck. The `unconfigured` / `ready` distinction is Calliopa's, layered above it.
- Detached runs are `POST /v1/runs` returning a run id, `GET /v1/runs/{id}` for status, and `GET /v1/runs/{id}/events` for the SSE stream. The body's field is `input`; a run's stream is `data:` frames carrying the event name inside the JSON, with `:` comment frames for keepalive and close.
- The release emits no run-started event. Its status moves `queued` to `running` and the stream's first frame is whatever the agent did, so the start the console draws is raised by Calliopa when the run is accepted rather than translated from anything.
- The pin is the part of this change that ages. A bump re-opens the two added dependencies, the asserted patch, and the config shape together, which the assertion exists to force rather than hide.

- Claude Code is pinned in the image (`@anthropic-ai/claude-code@2.1.251`), because the Claude runner passes it flags verified against that version: `--output-format stream-json`, `--tools`, `--strict-mcp-config`, `--allowedTools`, `--permission-mode dontAsk`, `--append-system-prompt-file`, and `${VAR}` expansion in `--mcp-config` headers. The runner also sets `DISABLE_AUTOUPDATER`, so the pinned CLI never replaces itself. A bump is re-verified the way the release patches are (`BO_0228_001`).
- `Dockerfile.hermes` builds the image on `python:3.13-slim` with the pin and its two added dependencies, the `claude` and `codex` CLIs on Node 22, and `ripgrep`. The build carries every assertion that cannot be made at run time: the elicitation patch fails the build when the release's source no longer matches, and the `mcp` major and the Node major are checked before the image is exportable, so a bump that breaks either is a red build rather than a quiet loss of HTTP MCP (`CA_0022_004`).
- The `hermes image` gate in `scripts/lib/verify-stack.mjs` proves the rest by behavior, because a Dockerfile comment proves nothing. It builds the image, starts the pinned release with a key it mints for the run, and waits for the release's own `/health` — which only answers when `aiohttp` gave the API server an adapter. It then issues an ordinary `proposer` credential in the verification database and connects `scripts/lib/hermes-mcp-probe.py` from inside the image to the tool surface in [Graph Gateway](../content-store/external-api.md), listing the tools and calling one. That connection is the pinned `mcp` line proving itself against a real server, which is the only honest test of a dependency whose failure mode is silence (`CA_0022_004`).
- The image carries no configuration and no credential. `hermes-entrypoint.sh` assembles both at start, so the image alone decides nothing about which runtime reasons or which client the agent is (`CA_0022_004`, `CA_0022_005`).
- `hermes-entrypoint.sh` assembles at start what the image deliberately does not hold: the API-server `.env`, the agent's own `cak_` credential written to the data volume, and the configuration naming the runtime. Secrets are read from a file or the environment into files under a restrictive umask and referred to by path afterwards, never passed as arguments, because an argument is readable from the process table by anything else in the container (`CA_0022_005`).
- The entrypoint supervises the gateway rather than replacing itself with it. When the settings surface writes new agent configuration to the shared volume, the entrypoint regenerates the configuration and restarts the gateway, which is why changing the runtime costs a restart and not a rebuild. It stamps the runtime it chose, so a surface reporting the active runtime reads a fact rather than inferring one from whatever answered (`CA_0022_005`).
- `HOME` points at the Hermes home on the volume, so the subscription credential homes the CLIs write survive a restart and a rebuild. That is the same decision that makes losing the volume mean signing in again (`CA_0022_005`).
- The `hermes image` gate proves the entrypoint alongside the release: that `/health` answers at all is the generated `.env` and `aiohttp`'s adapter proving themselves together, and the gate then asserts the default runtime was stamped, the credential reached the volume while staying out of both the image and the log, and that new agent configuration was regenerated without a rebuild (`CA_0022_005`).
