# Application Foundation

## Purpose

- This document is the authoritative description of the application's runtime boundary, development environment, and verification gate.
- `CA_0002_BUILD_technical-architecture-and-workspace-shell` is the originating change.
- The fixed stack in [System](../system.md) decides the language, framework, runtime, and services. This document decides how they are assembled and what must become true.

## Network

* The development machine is WSL with code-server, inside a Tailscale network. Containers are reached at the machine's Tailscale address `100.114.122.91`, not at `localhost`: Docker publishes ports to the Windows host rather than the WSL loopback, so `localhost` from a WSL shell does not reliably reach them while the Tailscale address does.
* This repo owns two host port ranges on `100.114.122.91` and publishes nothing outside them: 4500–4520 for development, and 4000–4020 for the production instance. The legacy `calliopa-web` stack (4310 / 5436 / 4910), `studio` stack (4400–4420), and `web` stack (4420–4440) on the same machine are never contended with, and neither range is reached by the verification gate, whose isolated projects publish nothing at all.

- The application listens on 4300 inside its container and is published on 4500. Postgres is published on 4501 and Garage's S3 API on 4502. Later services take the next free port in the range. Ports are overridable through the environment file.
- Hermes listens on 8642 inside its container and is published on 4503, for development inspection only and behind its own bearer. Honcho listens on 8000 and is published on 4504, and runs only when its key is stored.
- Production publishes the same services at the front of its own range, in the same order: the application on 4000, Postgres on 4001, Garage's S3 API on 4002, Hermes on 4003, and Honcho on 4004. 4005–4020 stays free for later services, and every port is overridable through the environment file as development's are. [Production Stack](./production-instance.md#production-stack) owns what runs there.

## Runtime Shape

- The application is one Qwik City app under `src/`. It serves server-rendered HTML routes and API routes.
- Since `BO_0207_016` the shell holds no records and no bytes of its own: content is the one graph's through CCGW, bytes are CCGW blobs, working state and secrets are the kernel's. [Episodes And Assets](../../../src/extensions/calliopa-video/docs/system/production/episodes-and-assets.md) owns what a rendition's bytes are, and a referenced blob is permanent in the graph's store.
- `/health` is the operational readiness probe. It reports CCGW and the kernel as reached rather than process liveness — `GET /healthz` on `CALLIOPA_CCGW_URL` and the agent bridge's health on `CALLIOPA_KERNEL_URL` — and answers 503 naming whichever did not answer.
- The application stays valid and renderable while the database holds nothing. An empty instance is a working state, and every gate run proves it.
- The `Dockerfile` has a `dev` target that runs Vite on 4300 and a `production` target that builds the client bundle and standalone Node server.

## What The Tree Depends On

- The tree carries no runtime dependency. `package.json` lists Qwik, Vite, TypeScript, Prettier and
  Vitest as dev dependencies and nothing else; `postgres` and `@aws-sdk/client-s3` left the
  lockfile with `BO_0207_016`, and Lexical left with the editor that used it. What a release ships
  is the built output, so until something is bundled into it no third-party library travels with a
  release at all.
- `package.json` and `pnpm-lock.yaml` are this extension's root-mapped members, and the kernel
  installs them with `pnpm install --frozen-lockfile` at materialization, so a dependency is
  resolved from the lockfile alone and a change to either is a write against the elevated
  extension.
- The tree's one runtime dependency is **`@mathjax/src`** (`BO_0290_023`, added 2026-09-23, pinned exactly at 4.1.3, Apache-2.0): `documents` typesets mathematics with it on the server and, lazily, in the browser ([Mathematics](../../../src/extensions/documents/docs/system/documents/block-editor.md#mathematics)). It is bundled into what a release ships rather than pulled at run time, which is why the distribution states what covers it (`calliopa-bootstrap`'s `BO_0290_021`).
- It is MathJax 4, not the `mathjax-full` package `BO_0163` used and this change first named: npm marks `mathjax-full@3.2.2` deprecated in favour of the scoped package, and making the tree's first runtime dependency a deprecated one would print a deprecation on every install for no gain. The engine is the one the user decided on either way. Its module paths are the same — `@mathjax/src/js/<path>` resolves to the package's ESM as `mathjax-full/js/<path>` did — so the server-side pipeline is unchanged in shape.
- Adding it left the build and the typecheck clean, checked in the container before it was staged. What it costs the client bundle is not yet known and is `BO_0290_014`'s to measure: nothing imports the renderer until the views do, so this dependency changed no bundle. The promotion gate's serve probe runs the built tree under a 128 MB heap, which is the bound that measurement is against.
- `citeproc` 2.4.63 — `citeproc-js`, the Citation Style Language processor — is a runtime dependency beside `@mathjax/src`, pinned exactly in `package.json` and `pnpm-lock.yaml` (`BO_0291_029`, landed 2026-09-24, under `calliopa-bootstrap`'s `BO_0291`). It is taken under AGPL-3.0-or-later of its dual licence (CPAL-1.0 or AGPL-3.0-or-later, as its `LICENSE` says; npm's metadata mislabels it AGPL-1.0) and used unmodified (user decision, 2026-09-24). The styles a release uses — IEEE, APA 7th and Chicago author-date — and the `en-US` locale alone (user decision, 2026-09-24) are the Citation Style Language project's files, CC-BY-SA-3.0, and the tree carries none of them: `csl-styles` and `csl-locales` are dependencies naming the project's repositories as GitHub tarballs at pinned commits (styles `8947960d`, locales `a89adece`), so pnpm fetches them when the interface is built and the lockfile holds their integrity, as it does `citeproc`'s (user decision, 2026-09-24, `calliopa-bootstrap`'s `BO_0291_038`). The styles tarball unpacks every style of the project — about 2,900 files in `node_modules` — for the three the bibliography imports with `?raw`; a build reaching the npm registry reaches `codeload.github.com` too. Only the bibliography's server imports the processor, so it is in the server bundle and in no client chunk; `bibliography` renders in-text labels and reference-list entries with it (`BO_0291_020`). `calliopa-bootstrap`'s `THIRD-PARTY.md` names both.
- [ ] BO_0296_011 A syntax highlighter joins `package.json` and `pnpm-lock.yaml` as the tree's third runtime dependency beside `@mathjax/src` and `citeproc-js`, pinned exactly and the lockfile regenerated in a real workspace, under `calliopa-bootstrap`'s `BO_0296`: `documents` colours a code block with it on the server and, lazily, in the browser while the block is edited ([Code And Its Output](../../../h/block-editor.md#code-and-its-output)). The choice is between `highlight.js` (BSD-3-Clause, coarse, small), `prismjs` (MIT, per-language files) and `shiki` (MIT, VS Code's TextMate grammars, the best colouring and the largest payload, each carried grammar under its own licence); it is recorded here with the reason, and how `THIRD-PARTY.md` names it follows `calliopa-bootstrap`'s `BO_0290_021`. `shiki` is the recommendation, because `calliopa-bootstrap`'s `BO_0296_008` sets a manuscript's code with Pygments and the two agreeing on grammars is worth more than a smaller bundle in a dependency nothing loads at read time.
- [ ] BO_0296_012 The engine cannot reach a reader, pinned as a source rule in `lib/highlight-boundary.test.ts`, the shape `lib/mathjax-boundary.test.ts` set (`BO_0290_019`): the assembler is the only module that imports the highlighter outright, the editing surface the only one that reaches it lazily, and no view imports it at all — so reading a coloured document fetches no grammar. Adding an ordinary import to a view fails it. Measured on a real build: which client chunk the engine lands in, its size, and that reading a document fetches none of it.

## Implementation

- The TypeScript Qwik City application lives under `src/`, uses exact pnpm dependencies and strict TypeScript, serves through Vite on port 4300 in development, and builds a standalone Node server. `src/server/ccgw/env.ts` is the environment the server needs — `CALLIOPA_CCGW_URL` and `CALLIOPA_KERNEL_URL`, both handed to the tree by the kernel — and the server entry reads it at startup, reporting every missing variable together (`BO_0207_016`). The multi-stage `Dockerfile` builds both `dev` and minimal `production` targets, and the empty `/` route renders `Calliopa` (`CA_0002_001`).
- `src/server/db.ts`, `src/server/object-store.ts`, `src/server/env.ts`, `config/required-env.json`, `migrations/` and the migration scripts are deleted under `BO_0207_016`, and `postgres` and `@aws-sdk/client-s3` left the lockfile. `scripts/serve.mjs` assembles nothing from secret files and migrates nothing; the promotion gate's serve probe reports nothing to skip. `/health` probes CCGW and the kernel concurrently and `src/server/health.test.ts` covers the decision and the probe boundary (`CA_0002_002`, `BO_0207_016`).
