# Device

## Purpose

- The shell on the Android and iOS apps: the same tree at the same release pin, built for a
  WebView inside the native host, with its server half running in the page behind a port that the
  device cell answers. The cell, the host, the sandbox and the release are the fixed layer's
  (`calliopa-bootstrap`'s `docs/system/mobile.md`); this topic owns what the tree does so that every
  feature built for the web reaches the device with no device-specific code.
- This topic carries the shell's half of `BO_0319`, transferred 2026-10-01. The scaffold's changes
  take over its port and device-build lines under their own identifiers as each is transferred:
  `CA_0074` the port, transferred 2026-10-01; `CA_0075`, the extensions' server halves on the port
  and the rule, and `CA_0076`, the device build, both transferred 2026-10-01.

## Fixed

* No feature has device-specific UI code. A feature the device cannot run yet is shown
  unavailable, never re-implemented for it. User decision, 2026-09-30 (`BO_0319`).
* A capability without its key or without network stays visible, disabled, says why in words and
  offers to add the key. User decision, 2026-09-30.
* An extension proposal can be read on the device and is never previewed or promoted there.
* The instance's behavior does not change: `build` stays what the kernel runs, and the web adapter
  is today's routes.

## The Port

- `src/server/port/` is the one interface the server half reaches the world through (`Port`, `port.ts`): the environment the frame reads (`CALLIOPA_CCGW_URL`, `CALLIOPA_KERNEL_URL`, `CALLIOPA_KERNEL_SESSION`, `CALLIOPA_KERNEL_CALLBACK_SECRET`), the clock, record identifiers, constant-time comparison of secrets, scopes that carry a value through a call and everything it awaits, the agent configuration files, the graph gateway, the kernel, and outbound fetch. A scope is an interface of the port rather than `AsyncLocalStorage`, because a WebView has none; the request context and the branch and pin scopes are scopes of the port. `CA_0074_001`
- The port answers the graph gateway and the kernel by route, not by operation. `gateway(path, init)` reaches CCGW under `CALLIOPA_CCGW_URL`: `/v1/cypher/query`, `/v1/cypher/mutate`, `/v1/cypher/explain`, `/v1/head`, `/v1/schema` and `/v1/blobs/…`. `kernel(path, init)` reaches the kernel under `CALLIOPA_KERNEL_URL`: `/__kernel/…`, which serves sessions, acceptance, proposals, document tools, party records, state records, attachments and runs. The device cell answers the same routes behind the bridge (`calliopa-bootstrap`'s `BO_0319_053`), so no operation is described twice. Each call rejects when its address is not set, and never guesses one.
- The agent configuration files are named relative to the directory the application and the agent share: `read` answers null for a file it cannot read, `exists`, and `replace` writes a file whole beside it and renames it into place, making its directory first.
- `#port` binds the adapter: `tsconfig.json` points it at `adapters/node-server/port.ts`, which `build`, the dev server and the suites resolve through `vite-tsconfig-paths`. The device build points it at its own (`CA_0076`). Nothing installs the port at start.
- `adapters/node-server/port.ts` answers the port on an instance with what the server half did before it: `process.env`, `node:crypto`, `AsyncLocalStorage`, `node:fs` under `CALLIOPA_AGENT_CONFIG_DIR` (default `/var/lib/calliopa/agent-config`, read by the adapter alone), and `fetch`. It reads every value when it is asked for rather than when it loads, so a suite that stubs the environment or `fetch` sees its own. `src/server/port/port.test.ts` holds the instance's answers to the port.
- The frame's own server modules reach Node, the environment and HTTP only through the port: `processes.ts`, `kernel-callback.ts`, `graph-gateway.ts`, `request-context.ts`, `workspaces.ts`, `registry.ts`, `ccgw/branch-scope.ts`, `ccgw/env.ts`, `agent/attachments.ts` and `agent/adapters.ts` under `src/server/`. The extensions' server halves, and the frame's clients they share (`ccgw/client.ts`, `kernel/`, `agent/bridge.ts`), still call what they called before, which the port leaves in place (`CA_0075_001`). `CA_0074_002`
- [ ] CA_0074_003 The frame's clients reach CCGW and the kernel only through the port's `gateway` and `kernel`, with no behavior change: `ccgw/client.ts`, `ccgw/blobs.ts`, `kernel/client.ts`, `kernel/extensions.ts`, `agent/bridge.ts`, `session.ts`, `licence.ts` and `health.ts` under `src/server/` still call `fetch` themselves. The device build needs it (`CA_0076_001`), and `CA_0075_002`'s rule refuses the bare `fetch` it leaves. Left open by the user's decision on 2026-10-01, when `CA_0074` kept to the ten modules it named.
- [ ] CA_0075_001 Every extension's server half reaches Node, the environment and HTTP only through the port, as the frame's own modules do (`CA_0074_002`), with no behavior change on an instance. At head 3751 twelve modules still do not: eleven take `randomUUID` from `node:crypto` — `bibliography`'s `works.ts`, `doc-block-roles`' `roles.ts` and `migrations.ts`, `documents`' `admonitions.ts`, `documents.ts` (with `randomBytes` for a change group's identifier), `focus.ts` and `work.ts`, `manuscripts`' `migrations.ts` and `tools.ts`, `media`'s `propose.ts`, `relations`' `relations.ts` — and `media`'s `media.ts` keeps the media sign-in's files under `CALLIOPA_MEDIA_CONFIG_DIR` with `node:fs`, `node:path` and `process.env`. The extensions' files are disjoint, so the work can be shared by extension. Verified by `check` and the behaviour suites passing unchanged.
- [ ] CA_0075_002 The rule: a test in `check` refuses a non-test module under `src/server/`, `src/routes/` or any extension's `server/` that imports a Node built-in (`node:*`, `fs`, `path`, `crypto`, `os`, …), reads `process.env`, uses `AsyncLocalStorage` or calls the global `fetch`, outside `src/server/port/` and `adapters/`, naming the file and what it reached. Verified by the test failing on each of a planted `node:fs` import, a planted `process.env` read and a planted `fetch` in an extension's server half, and passing on the whole tree.

## The Device Build

- The device build is `CA_0076`'s. It speaks the device cell's bridge as built (`calliopa-bootstrap`'s `docs/system/mobile.md`, *The Device Cell* and *The Native Host*): the `Cell` plugin's `call` takes one request — `protocol`, `method`, `path`, `header`, `body` or `bodyBase64` — and answers `protocol`, `status`, `header` and `body` or `bodyBase64`; a refusal by the routes is a response, and only the bridge's own error rejects. Bridge protocol 1.
- [ ] CA_0076_001 `adapters/device/port.ts` answers the port in a WebView: the graph gateway's and the kernel's routes as cell requests over the bridge, with their paths unchanged and no address; the clock, record identifiers, random bytes and constant-time comparison from the platform's Web Crypto; scopes without `AsyncLocalStorage`, how a scope carries a value across awaits in a page written here when measured; the configuration files absent, read answering null and a write refused in words saying that sign-in to a subscription or a media service is an instance's (`settings`' `BO_0319_049`); and outbound HTTP through Capacitor's native HTTP, which a page's cross-origin rules do not bind. Verified by `src/server/port/port.test.ts`'s cases run against the device adapter over a real cell.
- [ ] CA_0076_002 `build:device`: Qwik's client-rendered output of the same tree with `#port` pointed at `adapters/device/port.ts`, into a directory the host's `webDir` takes (`calliopa-bootstrap`'s `shell-device`, `BO_0331_001`), and the API routes under `src/routes/` dispatched in the page to the same handlers, so a request the client makes to `/api/…` is answered in the page with no server. At start the page asks the cell's protocol and, on a mismatch, shows the cell's refusal in words in place of the shell. `build`, the dev server and the suites are unchanged, and the kernel never runs the device build. Verified by `build:device` producing the directory, and by a pin building and serving as before.
- [ ] CA_0076_003 The behaviour suites run against the device build in a desktop harness: the page served from `build:device`'s output in a browser, its bridge answered by a real device cell over a local socket (`calliopa-bootstrap`'s `BO_0319_058`), the plugin's definition the one interface. Needs `CA_0075_001` and the kernel's operations in the cell (`BO_0319_053`). Verified by the suites passing there as on an instance, and by a planted second protocol showing the refusal.
- [ ] BO_0319_043 Capability states: each remote capability — agent runs per provider, search, page capture, media per vendor, embeddings — is declared with a state, *ready*, *needs a key*, *offline* or *unavailable on this device*, read from the port; every control that uses one is disabled while it is not ready, names the reason and links to the settings connection that fixes it. On an instance every capability the stack serves reads *ready*, so nothing changes there. Verified by the search control reading *needs a search key* with no key and *offline* in airplane mode.
