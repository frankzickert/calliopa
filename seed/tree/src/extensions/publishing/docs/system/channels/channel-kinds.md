# Channel Kinds

## A Kind Is Code

* A channel kind is an adapter this extension ships, one per platform or protocol, declared as a typed value against one contract. Adding a kind is adding one module and one registry entry; nothing else in the extension branches on a kind's name.
* A kind declares: its `id` and `label` and icon; the **credential** it needs — `apiKey` (a key the kernel presents), `oauth` (a token the kernel obtains and renews, once `BO_0252` lands), or `manual` (Calliopa prepares, a person publishes, the log records it); its configuration **fields** beside the credential, each with its check, and the **probe** that proves the pair; its **offer** — the slots it fills, each a content class ([Shapes And Deliverables](../shapes/shapes-and-deliverables.md)) with the constraints the platform imposes (aspect, duration, dimensions, formats, a text length, cardinality) — fixed in code for a platform and read from the destination for a website; the **units** it takes — a deliverable, an item, or its own front; the **acts** it supports — `publish`, and `retire` or `replace`, whichever the platform actually offers.
* A kind's **projection** is pure: a function from a deliverable or item, its binding and the channel's assignment onto the platform's document, answering the document or every rule it breaks, with no I/O. Its **transport** is the only code that reaches outward, and only through the kernel's brokered request, which adds the credential. The split is in the contract, so the ordinary gate proves every mapping and every refusal without an account or egress, and an environment-gated gate per kind proves the transport.
* A kind's descriptor is what the settings extension instantiates for each channel of that kind: the party record under `publishing-<channelId>` carries the kind's fields, authorization and probe with the channel's title as its label (`CA_0049`).
- The kinds this extension ships arrive one per change: `website` with `PU_0001`; Bunny Stream (`bunny-stream`, `PU_0004`); YouTube (`PU_0005`, after `BO_0252`); the `manual` kinds for Substack's weekly edition and Reddit's prepared draft (`PU_0006`); each redirect-flow platform after that. A kind's per-platform constraints are taken from the strategy's `destinations.yaml` in `calliopa-video/narrative` and verified against the platform before the kind is claimed.
* Bunny Stream is a kind of its own, `bunny-stream`, taking video items ([Bunny Stream](./bunny-stream.md)); a website channel's video slot names the Bunny channel that hosts it, and the website's projection carries the id that publication answered. User decision, 2026-09-14, reversing the analysis's reading of Bunny as a host a website channel names in its configuration.

- `server/kinds/contract.ts` declares the shape: `Kind` with `id`, `label`, `purpose`, `credential` (`CREDENTIAL_KINDS`), `fields` (the shell's `ConfigurationField`, so the settings row checks them as it checks any party's), `authorization` and `probe` (the kernel's `PartyAuthorization` and `PartyTest`, handed to the store when a channel is created), `offer` — a fixed `Slot` list, or `fromDestination` — `units` (`UNITS`) and `acts` (`ACTS`), and an optional `publish` half: a pure `project` answering `Projected<T>` — the document or every `Refusal` — and a `deliver` over a `Transport` whose one call is the kernel's brokered request. A kind without the half is one whose first publish has not been built, and the registry says so rather than pretending; `Refusals` collects every rule broken so an author is told the whole list. `server/kinds/registry.ts` lists the kinds present (`KINDS`, `kindOf`) and answers a kind as the browser is handed it (`summarize`: id, label, fields, whether it reads an index); it is a file of its own because the contract cannot import its implementations (`PU_0001_003`).
